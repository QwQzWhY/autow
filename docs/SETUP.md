# 部署说明

一次性配置，大约半小时。配好之后：**电脑关机不影响**，官网通知由云端定时抓取
（实际间隔几小时，见文末说明），QQ 群里 @全体成员 约一分钟内进待办，全程在手机上看。

```
GitHub Actions（云端）                       你的手机
├─ 定时抓学院 + 学校官网 ──┐  scan.yml
├─ 收到 QQ 消息立刻触发 ───┤  qq.yml ──> 大模型抽取 ──> docs/data/todos.json
└─ 提交回仓库 ─────────────┘                                │
                                                      GitHub Pages
                                                           │
                                                  待办看板（加到主屏）
                                                  通知桥 App（可选）
```

## 第一步：建仓库

1. 在 GitHub 上新建一个**公开**仓库，名字随意，比如 `autow`。

   > 为什么必须是公开的：GitHub Pages 免费版只给公开仓库用。通知本身是公开信息，
   > QQ 消息的原文从不落盘（见「隐私」一节）。不接受的话看文末的「用私有仓库」。

2. 推上去：

   ```bash
   cd AutoW
   git add -A
   git commit -m "初始化"
   git branch -M main
   git remote add origin https://github.com/<你的用户名>/autow.git
   git push -u origin main
   ```

   > 如果 `github.com` 连不上（国内常见，`api.github.com` 却正常），开代理后执行
   > `git config --local http.https://github.com.proxy http://127.0.0.1:7890`
   > （端口按你自己的代理改）。只对 github.com 生效，不影响其他域名。

## 第二步：配大模型

**Settings → Secrets and variables → Actions → New repository secret**，加三个：

| 名称 | 值 |
|---|---|
| `LLM_API_KEY` | 你的 API Key（`sk-` 开头那串） |
| `LLM_BASE_URL` | 接口地址，见下表 |
| `LLM_MODEL` | 模型名，见下表 |

> **这三个别填错。** 曾经把 Key 填进 `LLM_MODEL` 和 `LLM_BASE_URL`，结果程序
> 把配置原样发布到公开仓库，密钥就泄露了。记法：**地址是网址、模型是名字、
> 只有 Key 是 `sk-` 开头的那串。** 现在有测试和启动校验拦着这种错误。

| 服务商 | `LLM_BASE_URL` | `LLM_MODEL` |
|---|---|---|
| DeepSeek（便宜） | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-flash` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |

**没有 key 也能跑**，会自动退回规则抽取，只是准确率差、容易漏隐含的截止时间。
看板数据里的 `docs/data/health.json` 会写明本次用的是模型还是规则。

## 第三步：开启写入权限

**Settings → Actions → General → Workflow permissions** → 选
**Read and write permissions** → Save。否则云端跑完没法把结果提交回仓库。

## 第四步：开启 Pages

**Settings → Pages**：Source 选 `Deploy from a branch`，分支 `main`，目录 **`/docs`**。

一两分钟后，看板在 `https://<你的用户名>.github.io/autow/`。

## 第五步：跑第一次

**Actions → 扫描通知 → Run workflow**。跑完看 `docs/data/todos.json` 有没有内容。

> 这一步同时会回答一个重要问题：**学校的反爬会不会拦住 GitHub 的机房 IP**。
> 如果日志里一直是 412，就把采集留给你自己的电脑开机时跑。

## 第六步：装到手机

手机浏览器打开看板地址 → 「添加到主屏幕」。之后点开就是待办，勾选状态存在手机本地。

看板右下角的 **＋** 可以自己加待办：**粘贴通知**（大模型读原文抽取）或
**手动填写**（自己填标题和时间）。两种都走和 QQ 消息同一条云端管道，需要
手机上有仓库名和令牌——就是你配通知桥时填的那两个，看板会自动复用。

## QQ 群消息怎么进来

安卓的「通知使用权」能读到 QQ 弹出来的通知。**@全体成员 时 QQ 一定会弹通知**，
所以这条路覆盖你最关心的那类消息。它不碰 QQ 协议、不登录账号，主号零风险。

> 前提：**你手机上真的弹了那条通知**。所以「自己发的消息」不算——QQ 不通知自己的
> 消息；被设成免打扰的群也不算。管理员发言要在 QQ 里把那几个人设为「特别关注」。

> **"@全体成员" 经常是单独一条**，正文可能在它前面，也可能在它后面。通知桥为此保留
> 每个群最近几条消息（5 分钟内、最多 6 条），匹配到关键词时把**前后这一整段**一起
> 发上去，之后三分钟内同一群的消息继续用同一个编号追加。所以：
>
> - 正文在前、@全体成员 在后 → 接得上
> - @全体成员 在前、正文在后 → 接得上
> - 一条通知里合并了好几条消息（QQ 会这么做）→ 全都读，不丢
>
> 窗口从匹配那一刻算起，**不会因为群一直有话说而无限延长**（否则活跃群会把每条
> 闲聊都上传一次）。最多追加 5 条，每条最多 4000 字，整段最多 20000 字。

> **群公告**：QQ 把一条群公告当成普通群消息推进群里，通知里常见「群公告」三个字，
> 但**不一定带 @全体成员**。所以关键词表里单列了 `公告`，让这类消息也进来。

> **超长消息**：一段消息里每一行都完整保留，只砍超过 4000 字的**单条**，而且砍的地方
> 会写上「……（通知里只带了这么多，剩下的被系统截断了）」——云端看到这句，会在待办里
> 提醒你回群看全文。**通知本身就是被 QQ 截短的话，那半截在手机的任何字段里都不存在，
> 谁都拿不回来**（除非去碰 QQ 协议，那条路不走）。这种情况请自己把全文粘贴进看板，
> 或者直接手动加一条待办。

> **省调用**：一段消息发出去之前会等 8 秒，看这个群还会不会继续说——把拆成好几条
> 的通知合成一次调用，而不是每来一条就调一次模型。只有「@全体成员」而没有别的内容
> 的那种，干脆不发，因为模型对它只能回答"无事可做"。

> **默认关键词**已经是五个：`@全体成员`、`@所有人`、`有全体消息`、`有人@我`、`公告`。
> 中间两个是 QQ 自己在通知里加的标记（实测抓到过 `[有全体消息]王熙竣: @全体成员 …`），
> 加上它们可以防住 QQ 改文案；`有人@我` 覆盖**单独 @你**的情况，`公告` 覆盖群公告。
> **升级安装会自动补上新增的默认关键词**——只有当你从没动过那一栏时才会补，
> 自己写过的关键词不会被覆盖。
> 如果你想让**管理员的每条发言**都进来，把他们的名字加进这一栏——但注意是全文匹配，
> 名字太普通（比如"王老师"）会把群里提到他的闲聊也带进来。

### 方案 A：通知桥 APK（推荐）

比 MacroDroid 简单得多，三步：

1. 手机浏览器打开 **https://\<你的用户名\>.github.io/autow/qq.html**，
   在第 3 步选「通知桥 App」标签，点里面的 APK 链接下载安装
   （需要允许「安装未知来源的应用」）
2. 打开 App，填**仓库名**和**访问令牌**，保存
3. 点 **① 开启通知使用权**，在系统设置里勾上它；
   点 **③ 常驻通知**（顶部会变成 ✅）；点 **④ 关闭电池优化** 并允许

装好之后 App 顶部应该显示「版本 x.y」和几行 ✅，最下面是**「最近读到的 QQ 通知」**
——那是排查问题的唯一入口，它能看到通知的标题和正文，而云端只存长度。

不想要通知栏那条常驻通知？**再点一次 ③ 就关掉**（连带前台服务一起）。保活会变弱，
能不能撑住要自己试；顶部状态会显示「常驻已关闭」。

### 方案 B：MacroDroid（备选）

如果不想装 APK，或者 APK 在你手机上活不下来，可以用 MacroDroid——它是成熟应用，
保活经验更多，但要在一个手机上走十几步配置。菜单名取自 MacroDroid 5.x 简体中文界面，
个别较新的选项可能还是英文，按位置找。

1. 应用商店装 **MacroDroid**，确保授予**通知使用权**。
2. 新建**宏**，**触发器**用 `通知` → **`收到通知`**：
   - `选择应用程序`：勾 **QQ**
   - 文本筛选选 **`包括`**，填 `@全体成员`
     （是「包括」不是「包含」，英文原文 Contains）
   - `防止多重触发` 保持默认开启
3. **动作**选 **`HTTP 请求`**：
   - `请求方法`：**POST**
   - `链接`：接入页上那一项
   - `请求头参数`：三条键值对，`Authorization` / `Accept` / `Content-Type`
   - `内容正文`：`内容类型` 选 **application/json**，正文填接入页上的 Body
   - 勾上「阻止下一动作直到请求完成」
   - 勾上 `将 HTTP 返回状态码保存在整型变量中`，变量名填 `http_code`
4. **再加一个动作**排错：`If` → `http_code != 204` → 里面放 **`显示通知`**，
   内容 `AutoW 上传失败：{http_code}`。GitHub 收到事件返回的是 **204**。

Body 里的 `{not_title}`（群名）和 `{notification}`（正文）是 MacroDroid 的魔法文本，
输入框旁边有插入按钮，**不要手打**。

### 国产系统必须额外设置（ColorOS / MIUI / EMUI）

实测一台**一加 Ace 6 至尊版（ColorOS）**：只开「常驻」不够，从最近任务划掉应用，
系统会把进程连前台服务一起杀掉，而且**重新打开 App 也修不回来**。三处都得设：

| 设置 | 位置 |
|---|---|
| 最近任务加锁 | 最近任务里长按卡片 → 点锁图标 |
| 完全后台行为 | 设置 → 电池 → 应用耗电管理 → 通知桥 App → 允许完全后台行为 |
| 自启动 | 设置 → 应用 → 自启动管理 → 允许通知桥 App |

> 「电池不受限」和「**允许完全后台行为**」在 ColorOS 里是**两项不同的设置**，
> 前者只是不省电，后者才允许它在后台活着。少后者，划掉就彻底死。

App 自己也会补救：进程被划掉后用闹钟一秒重启（`onTaskRemoved` + `AlarmManager`），
监听断线时主动申请重连（`requestRebind`）。但没有上面三处授权，ColorOS 会拦住这些。

### 出问题时怎么查

**只看一个地方**：App 最下面的「最近读到的 QQ 通知」。

| 现象 | 处理 |
|---|---|
| 有新条目、✅ 已匹配 | 读到了，问题在上传。看上一行「最近一次」的报错 |
| 有新条目、⏭ 未匹配 | QQ 把关键词放在别的字段了 |
| **没有新条目** | 通知没弹（自己发的？群免打扰？），或监听被系统掐了 |

**换过 APK 之后、或者监听被系统杀掉之后，「通知使用权」的绑定会悬空**——设置里看着
还是开着的，但服务没接上。**把那个开关关一次再打开**就能修，这是唯一有效的办法。
App 里那行「监听上次接入：」是服务真正被绑定过的时间，比权限开关可靠。

### PAT 怎么建

**Settings → Developer settings → Personal access tokens → Fine-grained tokens**：

- Repository access：只选这一个仓库
- Permissions → **Contents: Read and write**（`repository_dispatch` 需要）
- 有效期建议 90 天

## 筛选口径可调

「这条通知跟我有关吗」由两个参数决定，改它们不用动代码。在线部署时用
**Settings → Secrets and variables → Actions → Variables** 设置：

| 变量 | 默认值 | 作用 |
|---|---|---|
| `AUTOW_STUDENT_PROFILE` | 兰州大学人工智能学院的本科生 | 你是谁 |
| `AUTOW_STUDENT_GRADE` | 2026 级（2026 年入学，现在是本科一年级） | 年级，决定推免、毕业这类该不该出现 |

改了会自动触发全量重新分析（抽取器签名变了），不用手动清缓存。

默认口径写在 `autow/llm.py` 的 `NOTICE_PROMPT`：**学生本人能主动报名、参加或提交的
都保留**（含自愿性质的考试与活动），**只有单位才能执行的行政事务、面向教师或研究生的、
不属于该年级的**丢掉。拿不准时宁可不推。**需要学院推荐才能参加的不会被丢掉，而是
单独成组显示**（看板底部「需学院推荐才能参加」）。

## 隐私

- 待办页面公开可访问，只是 URL 不为人知。**不要往里放私人信息。**
- `data/autow.db` 会随仓库走，所以：**QQ 消息的原文、群名、人名一概不落盘**，
  只留用于去重的摘要、判断结果和时间；聊天判断结果也不进缓存。
- 发布到公网的内容经过脱敏：健康状态文件只留主机名，看起来像密钥的值一律隐藏。
- PAT 只存在手机的应用私有目录里，除了 `api.github.com` 不发往任何地方。

## 用私有仓库

私有仓库 + 免费账号没有 Pages。折中办法：仓库设成公开但只发布摘要，或者不要网页看板，
改成在 workflow 最后调用 Bark / Server 酱把当天的待办推到手机。

## 常见问题

**官网通知多久抓一次？**
workflow 里写的是每小时（`cron: "0 * * * *"`），但**实测运行间隔是 5～7 小时**。
这是 GitHub 免费调度器的行为——官方文档写明定时任务在高负载期间会被延迟甚至丢弃。
不是代码问题，也没有便宜的解法。学校通知一般提前几天发布，这个频率够用。

**抓不到通知，日志里全是 412？**
学校的 WAF 拦了。云端机房 IP 可能比家里 IP 更严，那就把采集留给你自己的电脑开机时跑。

**扫描任务红了？**
先看是哪一步。如果是「提交结果」，多半是推送撞车——脚本会自动重试 5 次。
如果是「抓取通知」，看上面那条 412。

**待办不准？**
换个更强的模型（`LLM_MODEL` 改成 `deepseek-reasoner` 或 `glm-4-plus`），
或者改上面那两个筛选变量。
