1 建一个访问令牌

手机要往你的 GitHub 仓库投递消息，需要一个令牌。去 Fine-grained tokens 新建一个：

  • Repository access：只勾选 这一个仓库
  • Permissions → Repository permissions → Contents 选 Read and write
  • 有效期建议 90 天

2 填仓库和令牌

只存在这台手机里，除了 api.github.com 不会发往任何地方。

3 配到手机上

  1. 应用商店装 MacroDroid，并授予通知使用权
  2. 新建宏 → 点 添加触发器 → 分类选 通知 → 收到通知
  3. 选择应用程序：勾上 QQ
  4. 文本筛选选 包括，填 @全体成员
    注意是「包括」不是「包含」，英文原文是 Contains
  5. 防止多重触发 保持默认开启，别关
  6. 点 添加动作 → 选 HTTP 请求
  7. 请求方法 选 POST；链接 填下面第一项
  8. 请求头参数 里加下面三条键值对
  9. 内容正文：内容类型选 application/json，正文填最后那一项
  10. 勾上「阻止下一动作，直到请求完成」（新选项可能仍显示英文）， 再勾 将 HTTP 返回状态码保存在整型变量中，变量名填 http_code
  11. 再添加一个动作排错：If → http_code 不等于 204 → 里面放 显示通知，内容填 AutoW 上传失败：{http_code}
    GitHub 收到事件返回的是 204，不是 204 就说明出错了
  1. 手机浏览器打开 autow-bridge-1.6.apk（版本 1.6）， 下载后安装（需要允许「安装未知来源的应用」）。旧版本会保留，可以随时退回
  2. 装好后 App 左上角会显示「版本 1.6」——截图给别人的时候能看出是哪一版
  3. 想自己编译：仓库的 Actions → 构建通知桥 APK → Run workflow
  4. 打开 App，把下面的仓库和令牌填进同样的两个框
  5. 点「① 开启通知使用权」，在系统设置里勾上它
  6. 点「③ 保持后台常驻」。通知栏会出现一条「AutoW 正在监听」—— 这条通知不能划掉，它是让进程不被系统杀掉的关键。
    不喜欢这条通知的话，同一颗按钮再点一次就关掉它（连带前台服务一起）—— 保活会变弱，能不能撑住要自己试；顶部状态会显示「常驻已关闭」
  7. 点「④ 关闭电池优化」，在系统弹窗里选「允许」
  8. ColorOS（一加 / OPPO / realme）还要另外设三处，否则划掉应用就会停止监听：
    · 最近任务里长按本应用卡片 → 点锁图标
    · 设置 → 电池 → 应用耗电管理 → AutoW 通知桥 → 允许「完全后台行为」
    · 设置 → 应用 → 自启动管理 → 允许 AutoW 通知桥
  9. App 顶部应该都是 ✅，并且有一行「监听上次接入：MM-dd HH:mm」。 如果那一行是 ⚠️，说明系统没把监听接上，点「① 开启通知使用权」里那个开关关一次再打开

4 测试

点一下，从这台手机发一条假消息给云端。收到就说明整条链路通了。

通知桥只读 QQ 弹出来的通知，不登录账号、不碰聊天记录。主号零风险。
默认只转发含 @全体成员 的消息；管理员发言要在 QQ 里把他们设成 「特别关注」才会弹通知。

如果 @全体成员 和正文是分两条发的，它会自动把三分钟内同一个群的 后续消息接在一起，合成一条完整的待办。
